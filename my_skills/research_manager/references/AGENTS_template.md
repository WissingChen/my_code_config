## 3. 实验纪律（科研项目适用，与科研无关时删除本节）

- 每个实验绑定一个主假设和当前主矛盾。
- 看结果之前，先记录 baseline、预期性能区间、预期机制信号和各结果的对应动作。
- 每次运行后比较 baseline、预期、实际，并先定位哪条因果边断裂（实验有效性 → 干预 → 机制 → 目标 → 价值），再提修改方案。
- 下一个实验必须降低一个决策相关的不确定性；说明不了"改变了哪个判断"就不开跑。
- 新想法进停放区，除非它推翻当前问题或改变当前决策，否则不进入主线。
- 局部异常只有在能解释主要偏差时，才能取代主矛盾。
- 连续两轮没有缩小决策相关的不确定性，停止实验序列并重新界定问题。
- 被测模型与运行协议由所有者显式指定，不以配置文件的现值为准；动手前确认，改完报告。
- 单局结果按"机制已证 / 效果待证 / 单局噪声"分级表述；机制在工作不等于修复有效，不拿单局读数下结论。

## 4. 运行与部署纪律（工具仓/服务类项目适用，无关时删除本节）

- 生命周期脚本契约：`ops/tool` 一类脚本必须保持子命令接口稳定（`preflight` / `build` / `backup` / `install-service` / `start` / `stop` / `restart` / `status` / `health`），可以新增，不可改名或删除。
- 状态与产物解耦：运行状态、配置、数据库、日志、上传文件一律写入独立 state 目录（如 `runtime/state/<tool>/`），绝不写进 release 目录；运行时读取的配置文件在安装时用软链接接入。
- state 目录属主必须是服务用户；不要用 `id -un` / `whoami` 兜底——自动化由 root 触发时会把 state 交给 root，服务用户静默失权。
- 密钥来源优先级：环境变量 > `.env`（仅开发）> 配置字面量（仅测试）；敏感字段支持 `${VAR}` 占位；真实密钥绝不进仓库。
- 健康检查：HTTP 200 即健康；只查进程存活，不查全部上游依赖（避免偶发上游故障导致部署回滚）。

## 6. 禁止事项

1. ❌ 看结果之前没记录 baseline、预期区间和各结果的对应动作就开跑（§3）。
2. ❌ 连续两轮没有缩小决策相关的不确定性，仍继续追加实验（§3）。
3. ❌ 从旧报告或生成的状态快照推断当前政策（§9）。
4. ❌ 实验分支直接合并主线；成功方向走 promote 流程（§8）。
5. ❌ 运行状态、配置、数据库或真实密钥写进 release 目录 / 仓库（§4）。
6. ❌ 删除或改名契约接口（如 `ops/tool` 子命令）（§4）。
7. ❌ Agent 未经所有者给出明确版本号，自行 commit / push / 打 tag / 部署（§5）。

## 9. 真相层级（科研项目适用）

1. `AGENTS.md`：本文件，过程政策。
2. 元目录（`.kilo/`）的 `global.md`：方向索引与指针（不含目标与规则）。
3. 方向 `00-overview.md`：当前状态与主矛盾（只记现状，不堆历史）。
4. 已登记实验计划：冻结的假设与预期。
5. 运行报告：观测证据与判断。
6. 文献笔记：外部证据。
7. 生成的状态快照：一次性视图，不作依据。
