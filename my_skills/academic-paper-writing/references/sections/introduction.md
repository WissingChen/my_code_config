# 分节指南：Introduction

写或改引言时加载。场景文件（如 `scenario-iclr-benchmark.md`）的段落骨架优先于本文件；本文件管每段怎么写扎实。

## 动笔前：先倒推，再顺写

倒推（回答完才动笔）：

1. 我们解决什么技术问题，为什么没有现成答案？
2. 贡献是哪种类型（新任务、新指标、新问题、新技术）？
3. 贡献为什么能解决这个问题，带来什么新认知？
4. 如何用前人的工作把读者引到这个问题上？

顺写顺序：任务 → 前人工作引出挑战 → 我们的方案与贡献 → 为什么有效 → 实验一句话。

## 挑战段纪律（最重要）

- 挑战段围绕"我们真正解决的那个挑战"组织，不是综述这个领域有多难。
- 前人文献链的最后一个局限，必须正好是我们解决的挑战；对不上就说明链排错了。
- 禁止写法：先摆一个 naive 方案，再说我们改进了它。这会把工作读成低分增量补丁，即使实际工作并不增量。读者的兴趣来自挑战本身，不来自被扶着走。

## 方案段

- 一个贡献配多个优势，或两个贡献（第二个回应第一个剩下的挑战），都是合法结构。
- 避免只讲抽象洞见不落实管线步骤。只讲洞见会制造新颖性幻觉，审稿人会读成浅工作。
- 创新句给名字和一个核心属性；实现句只提技术名词，不展开每一步；优势句对着前人方法的具体局限说。

## 自查

- 每段首句是不是该段的论点？
- 挑战、技术原因、我们的解法三者是否都点名了？
- 引言里每个声明是否有实验撑着（SKILL.md §5）？
- 术语全文一致吗？
