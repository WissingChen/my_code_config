# 实现级事实采集模板 — knowledge_keeper §8 配套

只对方向最近的直接工作用。每篇论文填一块；存进该论文笔记的 `## Implementation facts` 小节，或在它要喂给"别人做到了哪"那步时放 `proposal/NN-slug/`。

```text
paper: <笔记文件名 / arXiv ID>    depth: metadata | abstract | full | code | reproduced
collected: <YYYY-MM-DD>           collector: <会话/agent>

## 它实际做了什么
- 输入 / 输出 / 数据 / 标签：
- 训练目标：
- 推理路径：

## 代码里的样子
- 核心模块（文件/类名）：
- 论文与代码一致性：一致 | 不一致：<哪里> | 无法核实：<原因>
- 头条数字背后的算力：<GPU 时 / 硬件 / 数据规模>

## 最优数字背后的条件
- 隐藏的预处理 / 筛选 / 调参：
- 作者自己报告的失败消融或负结果：
- 作者自己写的局限：

## 可用性
- 代码：<仓库 URL> | 无    License：
- 中间信号是否暴露：是 | 否 | 打补丁可以：<补什么>

## 缺口（明写，不许沉默）
- 没找到：<字段> — 查过 <哪里>，<日期>
- 无法核实：<字段> — 原因
```

规则：

- 每个字段要么带来源填上（文件路径、表号、日志），要么记进**缺口**。缺的事实要写下来，不是略过——这样 `research_progress` 才能如实给链条箭头打 `猜测`/`不知道` 标。
- 深度限制说法：只按 `abstract` 深度填的模板，最多支撑"值得读"。
- 重读时字段变了（比如代码后来开源了），原地更新并刷新笔记的 `quality-updated`。
