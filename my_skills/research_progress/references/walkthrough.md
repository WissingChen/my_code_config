# 填法实例 — research_progress

三个真实方向的完整收敛记录。示范每样东西写到什么程度，以及过程中踩过的坑。

说明：三个方向对应的论文是真实的（CRA、CMCRL、PhyScene3D）；文中的探针数字来自推演记录，真实填写时替换成实际实验数字。

---

## 例一：CRA — 视频问答定位的去偏

**初始想法**：VideoQA 可能依赖偏倚作答（参照 NextGQA 的观察）。用前门干预：完整视频 = X，定位出的片段 = M，回答 = Y。

**关键问答**：
- 谁被卡住：评测方分不清"模型没看懂"和"模型没看对地方"（NextGQA intro 的证据）。过。
- 怎么区分两种解释：VQA 涨而定位准度不涨 = 还在靠捷径。现成的信号，不用自建评测。过。
- 只对当前想法成立的问题：回答头吃进去的是什么张量？如果完整视频特征也进回答头，X→Y 就绕过了 M，前门公式不成立。回答：只喂片段特征（与 NextGQA 设置一致）。链条成立。

**弯路**：对干预方式做过推演式否定（"片段内帧间平均只是聚合，治不了捷径"），预言探针会失败。实测证据（CRA 论文，涨点显著，消融把干预模块和单纯双路特征分开了）打脸推演。教训写进了 SKILL.md §6：推演只配排优先级，不配当证据。

**六项结果**：
- 结论：通过
- 实际价值：把"真看了视频"和"靠问题先验猜"分开，让 VideoQA 分数重新可信
- 相关工作现实：图像侧前门干预已验证（无检测器、代码开源）；本次检索范围内视频定位上无同机制工作
- 实现链条：M = 注意力池化的片段特征；干预 = 均值池化对照；区分信号 = VQA/定位准度分叉。无断点
- 最大猜想：干预有效性与机制归因——被论文消融证据消除
- 下一项证据：全量训练与完整评测（即 CRA 本身）

## 例二：CMCRL — 放射报告生成的去混杂

**初始想法**：医学影像报告生成也可以用多模态因果干预提升鲁棒性。——空话起步。

**关键问答**：
- 通用清单式提问（谁的瓶颈/指标/混杂是什么）被用户指出模板化。真正推进的是只对当前想法成立的问题：领域已有重加权、对比学习，凭什么非因果干预不可？混杂长什么样？
- 回答给出混杂分型：语言捷径（前缀先验、模板句）、视觉捷径（看到病灶 A 就答共现病症 B）、跨模态。前两者具体，跨模态虚。
- 用户最初想用检测器/知识库路线，但手头没有 → 卡住。转换约束：不许用检测器，从特征内部构造中介 → 注意力挑局部细节、池化出全局轮廓，两半采样混合（逼近前门公式里"对组合取平均"）。

**探针与迭代**：只做视觉侧干预，异常描述改善，但模板句照旧——语言捷径没断。由此回答了一开始答不出的问题：两个中介必须并联融合后一次干预（串联互相打架，探针中指标回落）。

**六项结果**：
- 结论：通过
- 实际价值：报告模型不再靠背模板拿分，评测方能分清"写得流利"和"看得准"；异常漏报是真实临床风险
- 相关工作现实：现有手段是重加权、对比学习、外部知识图谱/检测器；本次检索范围内报告生成上无前门干预工作
- 实现链条：视觉中介（局部+全局采样混合）、语言中介（词概率统计）、并联一次干预；不需要检测器。无断点
- 最大猜想：两中介并联优于串联——被探针证据消除
- 下一项证据：全量训练与完整评测（即 CMCRL 本身）

## 例三：PhyScene3D — 物理一致的桌面场景生成

**初始想法**：本想用智能体方式做桌面布局，受 API 限额和 GPT-4o 性能限制，转向；看到 MesaTask-10k 数据集，想 follow。——"follow 数据集"是占坑，不是方向。

**关键问答**：
- "GPT-4o 性能差、高性能贵"是工程抱怨，且已被 MesaTask 自己的小模型解决。真正的对手是 MesaTask 模型本身：它的结构性缺陷是什么？
- 两个怀疑对象：物理站不住、不能交互。
- 最便宜的决定性验证：**先算数据本身**——逐场景测碰撞率，发现约 22% 场景带穿透（模拟数字）。数据本身就脏，谁训练谁继承。
- 重新提法：方向不是"在 MesaTask 上刷点"，而是"基于本身就不可靠的数据得到可靠的模型"。与带噪标签学习的差别：这里的噪声是物理的、可独立验证的——仿真器是免费的裁判。
- 机制选择：物理信号进训练（而非生成后修正），用可微几何近似（穿透深度、支撑关系、重心投影）绕开仿真器不可微的问题。

**探针与迭代**：只加穿透惩罚，碰撞率大降但堆叠物体在真仿真器里仍塌——几何近似不知重心。补上支撑关系 + 重心投影两项后通过。

**六项结果**：
- 结论：通过
- 实际价值：具身任务需要能放进仿真器的场景；公开基准数据本身带碰撞，使用者被迫继承噪声
- 相关工作现实：MesaTask-10k 提供了缺失的公开协议，但数据与 baseline 都不保证物理性
- 实现链条：脏数据训练 + 可微几何惩罚进损失；仿真器只做最终裁判不进梯度。无断点
- 最大猜想：几何近似够用、不必真仿真进训练——被探针证据支持
- 下一项证据：全量训练 + 物理一致性/交互性评测（即 PhyScene3D 本身）

## 三个例子共同踩过的坑

1. **模板问法是负资产**。真正推进的全是只对当前想法成立的问题（"回答头吃什么张量""GPT-4o 错在哪"）；通用清单每轮都被打断。
2. **不许预测实验结果**。例一中凭推演预告失败，被实测打脸。
3. **先算数据，再谈方法**。例三最有决定性的动作是花几小时算数据集碰撞率，不是设计方法。
4. **重新提法是真进展**。例二的混杂分型、例三的"脏数据 + 物理裁判"——提法变了，方向才立住。
